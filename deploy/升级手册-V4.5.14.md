## 1. 本次修了什么

### 1.1 根因：表头里的一个制表符，让 122 行全部读不进

你上传的 `holidays.csv` **本身没有问题**，是代码没读懂它。文件原始内容长这样：

```
"日期<TAB>","类型"              ← 表头的「日期」后面跟着一个制表符
"2026/1/1<TAB><TAB>…","休"      ← 值后面也跟着一串制表符
```

这是 Excel 导出 CSV 时把单元格里的制表符一并写了出来。于是程序解出的列名是 `日期<TAB>` 而不是 `日期`，取值时恒为空，**文件里 122 行数据被逐行静默跳过**。

值本身是好的（程序能正确把 `2026/1/1<TAB><TAB>…` 解析成 `2026-01-01`）——**唯一的失败点就是表头那一个制表符**。

已修：读 CSV 时统一规范化表头（去掉前后空白与制表符）。本系统读 xlsx 的路径一直有这道处理，读 CSV 的路径漏了。

> 这与 V4.4.1 那次（`holidays.csv` 存成 GBK 导致整个倚天域不重建）**同源**：都是「Excel 导出的 CSV 格式脏」。同一个文件第二次出事，所以这次把表头容错一并做进去了。

### 1.2 为什么提示说「未提供」——第二个缺陷

判断「要不要降级成纯周一~周五」看的是**解析结果**（读没读到休/班行），不是文件在不在。于是"文件在、但一行没读懂"和"文件根本没上传"落进了同一个分支，而告警文案写死了「未提供」——**结果就是指引你去反复重传一个已经在位的文件**。

已修：告警分两种说法。

- 文件不存在 → 「未提供 input/yitian/holidays.csv……」（同旧文案）
- **文件在但一行没读懂** → 「input/yitian/holidays.csv 已上传但一行都没读懂（表头是否恰为「日期,类型」？用 Excel 导出时常把单元格里的制表符一并写进表头）……」

### 1.3 修复前，倚天的数据错了多少

以你那份 `holidays.csv` 实测（覆盖 2026 全年，115 个「休」+ 6 个「班」）：

- **19 个法定假日**（落在周一~周五）被错当成工作日
- **6 个调休上班日**（落在周末）被错当成休息日
- **净多算 13 天工作日**

按月分布，**2 月 6 天（春节）、10 月 5 天（国庆）**最严重。

后果：这些周期的饱和度分母每多算一天就多 8 小时，**饱和度被系统性低估**；节假日期间没填工时的人还会被误报成「欠填」。

升级并点过「更新数据」后，这些数字会**变准（普遍升高）**，误报的欠填也会消失。这不是数据被改坏了。

## 2. 升级步骤

### 2.1 备份

```bash
cd /opt/pmplatform          # 换成你的实际部署目录
tar czf ~/pmplatform-backup-$(date +%Y%m%d-%H%M).tar.gz .
```

### 2.2 上传并解压

```bash
# 把 pmplatform-update-V4.5.14.zip 传到 /tmp
cd /tmp && unzip -o pmplatform-update-V4.5.14.zip
```

### 2.3 覆盖后端代码与前端产物

```bash
cd /tmp/pmplatform-update-V4.5.14
cp -f *.py /opt/pmplatform/
rm -rf /opt/pmplatform/frontend/dist
cp -r frontend/dist /opt/pmplatform/frontend/
```

### 2.4 重启后端

```bash
sudo systemctl restart pmplatform
sudo systemctl status pmplatform --no-pager
```

### 2.5 ⚠ 点一次「更新数据」（本次必须）

浏览器进 `/data` → 「更新数据」。

**不做这一步，倚天的工作日仍是旧的错值**——修复在管线里，要重新跑一次才会把 `holidays.csv` 正确读进去、重建 `yitian_data.json`。

进度跑完后，`/yitian` 顶部那条黄色告警应当**消失**。

## 4. 如果你暂时不想升级——手工解封

用**纯文本编辑器**（记事本 / VSCode，**不要用 Excel 重新另存**）打开 `input/yitian/holidays.csv`，把第一行改成：

```
日期,类型
```

也就是把「日期」后面那个制表符删掉，保存后点「更新数据」即可。

升级之后就不必再管——代码已永久兼容这类脏表头。

## 5. 回滚

```bash
sudo systemctl stop pmplatform
cd /opt/pmplatform && tar xzf ~/pmplatform-backup-<时间戳>.tar.gz
sudo systemctl start pmplatform
```

回滚后需再点一次「更新数据」，倚天数据会退回旧的（错误的）工作日口径。
`holidays.csv` 本身不受影响。
