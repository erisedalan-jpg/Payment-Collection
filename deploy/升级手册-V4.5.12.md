## 1. 本次修了什么

### 1.1 ⚠ 归档会永久销毁「页面上看不见」的跟进内容（这条是重点，请读完）

**问题**：五张跟进表（临时重点跟进 / 风险跟进 / 回款重点跟进 / 重点商机跟进 / 重点项目进展）点「更新（归档）」时，
存进历史快照的是**页面上当前看得见的那些行**，而清空动作却作用于**后台的全部记录**。
两者的差值 —— 也就是**页面上看不见的那些记录** —— 会被清掉，且从未进过任何一份历史快照，
**内容彻底消失、没有任何提示、也无法从「历史数据」里找回**。

**什么情况下会有「看不见的记录」**（正常手工填写不会产生，因为要先看得见才填得了）：

1. **蓝信回复归入**写进来的（V4.5.10 加了二次确认，但仍允许写入）；
2. **范围设置被改小**之后，原先在范围里、现在掉出去的项目；
3. **数据更新之后**，项目属性变了不再命中范围条件的；
4. 「重点项目进展」页还有一种：项目**不再是重点项目**（降级、或合同金额变化）之后。

**修复后的行为**：归档只清空「本次快照真正收录了的那些记录」，范围外的记录**原样留在后台**
（不清空、也不进本次快照）。等范围设置改回来、或项目重新进入范围，内容照旧显示。

**归档后会多一句提示**：
- 正常情况（没有范围外记录）→ 绿色「已归档」；
- 有范围外记录 → 橙色「已归档。另有 **N** 条记录不在当前范围内（页面上看不到），已原样保留 —— 未被清空，也未进入本次归档快照。」

> **★ 这句提示里的 N 值得看一眼**：如果 N **等于该表的全部记录条数**（即一条都没归档进去），
> 说明前端行结构与后端约定的主键字段对不上了，属于异常，请截图反馈。正常情况下 N 应该是 0 或一个小数字。

> **⚠ 升级前已经被销毁的内容找不回来。** 本次修的是「从今以后不再发生」，
> 已经发生过的销毁没有任何留痕（这正是它此前难以察觉的原因），无法恢复。

**受影响范围比最初判断的广**：最初以为只有「临时重点跟进」一张表受影响，
逐个核对代码后确认**五张表全部受影响**，只是触发条件不同 ——
临时跟进 / 重点商机跟进 / 重点项目进展是**整条记录**销毁；
风险跟进 / 回款重点跟进是在超管**配过「归档时清空」的自定义列**时，销毁那一列的值。

### 1.2 下钻弹窗里的长表格会把对话框撑破

**问题**：各处图表/卡片点进去的下钻弹窗（回款多维分析的项目下钻、数据管理的节点下钻、
项目分析的项目下钻、里程碑的两个下钻、风险下钻）里的表格**没有任何高度限制**。
点开一个上百条的下钻，对话框会被撑到几千像素高，滚动条滚的是整个遮罩层而不是表体，
表头也留不住 —— 往下滚就不知道哪一列是哪一列了。

**修复后**：弹窗里的表格**表头冻结、表体内部滚动**，高度按当前浏览器窗口算
（窗口越高表格越高；1366×768 的笔记本上约 8 行，1080p 全屏约 15 行）。

另外，其中**两个**弹窗（回款多维分析的项目下钻、数据管理的节点下钻）此前有个
**静默截断**：超过 200 条时只渲染前 200 条，**页面上没有任何提示**，用户不会知道自己
看到的不是全部。本次保留 200 条上限（表格控件没有虚拟滚动，上千行会明显卡顿），
但改为**显式告知**：「共 N 条，此处只显示前 200 条（另有 M 条未列出）；请在页面上收窄筛选后再下钻。」

## 2. 升级步骤

以下命令假设应用装在 `/opt/pmplatform`、服务名 `pmplatform`，请按实际情况替换。

### 2.1 备份（务必先做）

```bash
cd /opt
sudo tar czf pmplatform-backup-$(date +%Y%m%d-%H%M).tar.gz pmplatform
ls -lh pmplatform-backup-*.tar.gz
```

### 2.2 上传并解压更新包

```bash
cd /tmp
# 把 pmplatform-update-V4.5.12.zip 传到 /tmp
unzip -o pmplatform-update-V4.5.12.zip
ls pmplatform-update-V4.5.12/
```

### 2.3 覆盖后端代码与前端产物

```bash
sudo systemctl stop pmplatform

# 后端 .py（更新包里是全部根级 .py，直接整体覆盖）
sudo cp /tmp/pmplatform-update-V4.5.12/*.py /opt/pmplatform/

# 前端 dist：先删旧的再拷新的，避免残留旧 hash 文件
sudo rm -rf /opt/pmplatform/frontend/dist
sudo cp -r /tmp/pmplatform-update-V4.5.12/frontend/dist /opt/pmplatform/frontend/

# pmisdata 脚本（如果这台机器在用「下载数据」功能）
sudo cp /tmp/pmplatform-update-V4.5.12/pmisdata/* /opt/pmplatform/pmisdata/ 2>/dev/null || true

sudo chown -R pmplatform:pmplatform /opt/pmplatform   # 按实际运行用户替换
```

> **⚠ 不要覆盖服务器上的 `data/`、`input/`、`pmisdata/config.json`。**
> 更新包里**本来就不含**这三样：`data/` 是你的业务数据与账号，`input/` 是数据源，
> `pmisdata/config.json` 存的是超管在页面里贴的 PMIS 会话 cookie —— 用开发机那份覆盖过去，
> 「下载数据」会立刻失效，而报错长得像「PMIS 登录过期」，很难想到是升级覆盖导致的。

### 2.4 重启并确认

```bash
sudo systemctl start pmplatform
sudo systemctl status pmplatform --no-pager
```

浏览器**强制刷新**（Ctrl+F5 / Cmd+Shift+R），确认左上角版本号变成 **V4.5.12**。

> 版本号没变 = `dist` 没换成功，或浏览器还在用缓存。先强刷，再检查 `dist` 目录时间戳。

## 4. 本次仍未验证的部分（如实说明）

**本次改动一次都没有在浏览器里实际看过**（开发侧无浏览器环境），全部结论来自代码与自动化测试
（后端 1422 项、前端 2283 项，全绿）。具体地：

- 弹窗内表格的**实际观感**（高度是否舒服、表头冻结是否生效）只在代码层算过，没有实拍。
  1366×768 笔记本上算出的可用高度约 384px（≈8 行），若你觉得偏矮可以反馈，改一个常量即可。
- 归档提示的**实际文案效果**（橙色告警的措辞长度、是否会被截断）没有实拍。
- 「范围外记录」这个场景本身**没有在真实数据上复现过** —— 要造出这个场景，需要先归入一条
  范围外的蓝信回复、或临时把范围设置改小。如果你愿意验一次，第 3 节第 2~5 条就是完整路径。

## 5. 回滚

```bash
sudo systemctl stop pmplatform
cd /opt
sudo rm -rf pmplatform
sudo tar xzf pmplatform-backup-<你刚才的时间戳>.tar.gz
sudo systemctl start pmplatform
```

> **⚠ 回滚到 V4.5.11 会让 §1.1 那个缺陷重新生效**（归档又会销毁范围外的内容）。
> 回滚后请暂时避免在五张跟进页上点「更新（归档）」，直到重新升上来。
> 数据文件（`data/`）本次升级不改写，回滚不会丢数据。

  日常升级走的是本更新包（用通配符收全部 `.py`），**不受影响**。

  H5 提交没有幂等，同一张卡刷新后可重复提交。
