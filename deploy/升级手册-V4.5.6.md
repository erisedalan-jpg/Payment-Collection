## 1. ⚠ 升级前必做：准备 `input/产品分类.xlsx`

本次新功能（产品大类、是否渠道商可交付、以及核心指标「可转移非原厂支持」）**全部依赖这张新表**。

- 文件名必须是 **`产品分类.xlsx`**，放在服务器的 **`input/` 根目录**（与 `TOP1000.xlsx` 同级）。
- 三列：`产品线` | `产品大类` | `是否渠道商可交付`。
- 「是否渠道商可交付」列**只认精确值 `渠道商可交付产品`**，其余（含空、「待评估」等）一律按「不可交付」处理。
- 也可以升级后在 `/data` 页上传（已进上传白名单），但**必须在点「更新数据」之前放好**。

**不放会怎样**：不会报错崩溃，但产品大类全部落空、「渠道商可交付」全判为否 → **「可转移非原厂支持」会全部落进「不可转移：非渠道可交付产品」，头条指标直接归零**。页面会在三处显式告警（`/yitian` 总览的数据就绪度卡、`/data` 页倚天卡、「更新数据」日志里的 `[WARN]`），不会静默。

## 2. 使用者会察觉的三处变化（请转达）

### 2.1 倚天「工时分析」tab 从 4 个变成 6 个

原有：合规检查 / 统计分析 / 趋势分析 / 客户支持分析
新增：**客户与产品分析** / **工时治理监控**

侧栏没有变化（仍 23 项），新页在「倚天工时 → 工时分析」点进去后的页内 tab 条里。

### 2.2 `/yitian` 总览页多了一张卡

顶部新增「**可转移非原厂支持**」五档分布 + 「数据就绪度」四个数字。后者是前者的可信度说明——校准覆盖率越低、客户不可归属工时越多，上面那个结论的水分越大。

### 2.3 两处既有页面有小幅增强

- `/yitian/analytics` 员工明细表**选列面板里多了 5 个列**（非面向客户 / 面向客户 / 项目类 / 售前类 / 售后类），**默认不勾选**，需要的人自己打开。
- `/yitian/trend` 粒度选择器**多了「半年」「年」两档**。注意：当前累积库跨度不足一年，选「年」只会得到 1 个点、选「半年」2 个点——这是数据跨度所致，不是故障，随累积库增长会自己变多。

## 3. 升级步骤（Ubuntu，约 4 分钟）

```bash
# 0) 上传并解压
cd /opt   # 按实际部署路径调整
unzip -o pmplatform-update-V4.5.6.zip
cd pmplatform-update-V4.5.6

# 1) 备份 dist 与后端（本次不改写 data/，但仍建议整体备份一次）
APP=/opt/pmplatform          # 按实际路径调整
cp -r $APP/frontend/dist $APP/frontend/dist.bak-$(date +%Y%m%d)
mkdir -p $APP/.pybak-$(date +%Y%m%d) && cp $APP/*.py $APP/.pybak-$(date +%Y%m%d)/

# 2) 覆盖后端（本次后端有改动，必须覆盖；含两个新增模块）
cp *.py $APP/

# 3) 覆盖前端 dist
rm -rf $APP/frontend/dist && cp -r frontend/dist $APP/frontend/

# 4) 放置新增输入文件（见 §1；若已在 /data 页传过可跳过）
#    cp 产品分类.xlsx $APP/input/

# 5) 重启后端
sudo systemctl restart pmplatform && sleep 2 && systemctl is-active pmplatform

# 6) 浏览器 Ctrl+F5 硬刷 /pm，左上角版本号应为 V4.5.6
```

### 7）**点一次「更新数据」**（本步不可省）

进 `/data` 页 → 点「更新数据」→ 等 SSE 进度跑完。

日志里应能看到这两行（数字随数据变化，格式应一致）：
```
[INFO] 产品线校准: 待校准 NNNN 行,已校准 NNN 行(NN%),多义 NNN,零命中 NNN
[INFO] 客户不可归属: NNN 行 / NNNN h(可转移判定的盲区)
```

**若出现下列任一 `[WARN]`，说明源表没配好，停下来处理再往下**：
```
[WARN] 未提供 input/产品分类.xlsx,产品大类与渠道可交付判定将全部落空
[WARN] 产品分类.xlsx 存在但解析出 0 行(表头是否含「产品线」?)
[WARN] TOP1000.xlsx 未找到「象限」或「客户象限」列,可转移判定将失真
[WARN] 组织架构表无「直接上级工号」列,管理干部识别不可用
```

> **不点「更新数据」会怎样**：倚天数据文件仍是旧结构，两个新页面与总览新卡**全部显示 0**，看起来像功能没生效。这不是 bug，是数据没重建。

## 4. 升级后验证清单

### 4.1 必须先过的两条（不过就回滚，别往下走）

1. **版本号**：左上角显示 **V4.5.6**。
2. **`/yitian` 总览页顶部「可转移非原厂支持」卡有非零数字**，且下方「数据就绪度」的「产品大类覆盖」显示 `N/N`（两个数相等，即 100% 覆盖）而**不是「未提供」**。
   - 若显示「未提供」→ `input/产品分类.xlsx` 没放对，回 §1。
   - 若五档全是 0 → 没点「更新数据」，回 §3 第 7 步。

### 4.2 新页面（超管或已授权账号）

3. 「倚天工时 → 工时分析」下有 **6 个 tab**，其中「客户与产品分析」「工时治理监控」为新增。
4. **客户与产品分析**页：五档 KPI、客户支持情况、TOP1000 覆盖度、客户支持清单（默认 50 行，可切全部）、两张热力图（行维度分别是「客户分级」和「L4 组织」）、客户×产品交叉图。
5. **工时治理监控**页：三个异常指标卡（售前服务类未关联产品 / 客户不可归属 / 产品线校准覆盖率）+ 两张明细表 + 项目管理工时概况（组织级 + 个人级）。
6. **筛选联动**：工具栏选一个产品大类或 L4 → 两个新页的数字全部跟着变。

### 4.3 既有页面没被拆坏（本次改了这两页，重点验）

7. **`/yitian/analytics`**：选列面板出现 5 个新列且默认不勾选；勾上后有值、能排序；**分页与列筛选仍正常**（本次改了该表的行数据源，这条专门验它）。
8. **`/yitian/trend`**：粒度多了「半年」「年」；**切回「周/月/季」结果应与升级前一致**。

### 4.4 权限

9. 用一个「可访问页面」不含新页的普通管理员登录 → **看不到那两个新 tab**。
10. 超管在账号管理里给需要的账号勾上「客户与产品分析」「工时治理监控」→ 该账号重新登录后可见。

> **注意**：`allowedPages` 是「全部页面」的账号自动获得新页；**逐页授权的账号需要超管手动补勾**，不会自动获得。

## 5. 已知边界（不是故障，不必报障）

| 现象 | 原因 |
|---|---|
| 「TOP1000 覆盖度」表只有一行 | 当前 `TOP1000.xlsx` 里的客户全部属于「市场BG3」。换一份含多个市场BG 的清单即自动多行，无需改代码。 |
| 趋势页选「年」只有 1 个点、「半年」2 个点 | 累积库跨度不足一年。随每周导入自动增长。 |
| 「可转移非原厂」的百分比偏高 | 当前 `TOP1000.xlsx` 是精简版（139 家），部分战略客户不在其中而被判为「可转移」。**换一份更全的 `TOP1000.xlsx` 覆盖上去、再点一次「更新数据」即自动收敛，无需改代码。** |
| 「产品线校准覆盖率」只有两成左右 | 校准只采纳「工作成果里唯一命中某条产品线关键词」的记录，多义的一律留白不猜。要提高覆盖率，超管可在倚天规则配置里补关键词，改完即时生效、无需重新部署。 |
| 客户不可归属有一批工时 | 客户字段填了占位词（如「受影响的客户」）。这是填报习惯问题，治理监控页就是用来盯它的。 |

## 6. 回滚

```bash
APP=/opt/pmplatform
D=$(date +%Y%m%d)   # 或改成实际备份日期
sudo systemctl stop pmplatform
rm -rf $APP/frontend/dist && cp -r $APP/frontend/dist.bak-$D $APP/frontend/dist
cp $APP/.pybak-$D/*.py $APP/
sudo systemctl start pmplatform
```

**回滚后需注意**：`data/yitian_data.json` 已被新版重建、带有新字段。旧版前端读它**不会报错**（多余字段被忽略），倚天各页正常。若仍不放心，回滚后再点一次「更新数据」用旧版重建即可。

`data/` 下的账号、跟进记录、规则配置等**本次全程未被改写**，回滚不涉及。
