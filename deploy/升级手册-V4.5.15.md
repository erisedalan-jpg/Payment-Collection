## 1. 本次修了什么

### 1.1 根因：浏览器用 `<div>` 装「回车换的新行」，而净化函数把它拆了却没补换行

跟进格是富文本编辑器。出于安全，保存前会用严格白名单净化一遍 HTML：白名单外的标签**拆掉外壳、保留里面的内容**（这样 `<a href="javascript:...">x</a>` 会被削成 `x`，脚本无处藏身）。

问题在于：浏览器的可编辑区里，**按回车换的新行是用块级容器 `<div>` 装起来的**。实测 Chrome 151，在编辑框里敲「第一行 ⏎ 第二行」，得到的是：

```
第一行<div>第二行</div>
```

`<div>` 不在白名单里 → 外壳被拆掉 → 只剩 `第一行第二行`。**换行就是在点「保存」的那一刻被吃掉的**，没有任何报错或提示。

已修：拆解块级容器时补回换行载体 `<br>`（`<br>` 本来就在白名单里）。上面那段现在会存成 `第一行<br>第二行`。

### 1.2 为什么它看起来「时灵时不灵」

三个表象叠在一起，很容易让人以为是偶发：

1. **连按两次回车（空一行）反而留得住换行**。空行的 HTML 形态是 `<div><br></div>`，里头那个 `<br>` 在白名单内，拆掉 `div` 后正好剩一个 `<br>`。
2. **Shift+回车一直是好的**。编辑框的样式里保留了原始换行，浏览器在这种样式下把 Shift+回车写成一个真正的换行符（不是 `<div>`），因此不受影响。
3. 从 Word 或网页**粘贴**进来的多段文字用的是 `<p>`，同样被拆掉 —— 粘贴进来的段落也会被压成一行。这次一并修好。

### 1.3 影响到哪些地方

全站的富文本填写格共用同一个净化函数，所以是**一处修好、全部修好**：

- 重点项目进展
- 回款重点跟进（跟进动作 / rev 结论）
- 风险跟进（跟进动作 / rev 结论）
- 重点商机跟进（本周工作进展 / 后续工作计划）
- 临时跟进（各实例）
- **以及四张跟进表下超管配置的全部「文本」类自定义列**

### 1.4 ⚠ 已经存过的老内容找不回来

换行是在**保存那一刻**就被丢弃的 —— 数据库里从来没有存过它。所以：

- **本版只保证「此后新编辑的内容」不再丢换行**；
- 之前被压成一行的老记录，**需要人工重新编辑补回换行**，系统没有办法还原。

## 2. 升级步骤

### 2.1 备份

```bash
cd /opt/pmplatform          # 换成你的实际部署目录
tar czf ~/pmplatform-backup-$(date +%Y%m%d-%H%M).tar.gz .
```

### 2.2 上传并解压

```bash
# 把 pmplatform-update-V4.5.15.zip 传到 /tmp
cd /tmp && unzip -o pmplatform-update-V4.5.15.zip
```

### 2.3 只替换前端产物

```bash
cd /tmp/pmplatform-update-V4.5.15
rm -rf /opt/pmplatform/frontend/dist
cp -r frontend/dist /opt/pmplatform/frontend/
```

包里也带了 `.py`，但**与线上完全一致**，覆不覆盖都行；不覆盖就不必重启。

> 若你习惯整包覆盖：`cp -f *.py /opt/pmplatform/` 后 `sudo systemctl restart pmplatform`，同样正确。

## 3. 验证清单

1. 浏览器 **Ctrl+F5** 强刷，版本号显示 **V4.5.15**。
2. 进「回款重点跟进」，点开任一「跟进动作」格：
   - 打一行字 → **按回车** → 再打一行 → 点「保存」。
   - **表格里应显示成两行**。再点开该格，编辑器里也仍是两行。
3. 反向确认净化没有被改松（安全回归，可选）：
   在编辑格里粘贴 `<img src=x onerror=alert(1)>` 后保存，**不应弹窗**，格内应为空。
4. 抽查一个自定义文本列（若有配置），回车换行同样保住。

## 4. 回滚

```bash
cd /opt/pmplatform && rm -rf frontend/dist
tar xzf ~/pmplatform-backup-<时间戳>.tar.gz frontend/dist
```

回滚后回车换行会重新失效，但已存的内容不受影响（存的是 `<br>`，旧版本同样认得）。
