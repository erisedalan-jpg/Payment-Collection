# 升级手册 —— V4.5.3（自 V4.4.6 起累积七个版本）

> 适用：已用 /pm 部署在 Ubuntu 服务器（nginx:80 → app 127.0.0.1:8080，systemd，`/opt/pmplatform`，venv `/opt/pmplatform/.venv`）。
> 现网基线 **V4.4.6** → 目标 **V4.5.3**，中间跨 V4.4.7 / V4.4.8 / V4.4.9 / V4.5.0 / V4.5.1 / V4.5.2 / V4.5.3 共七个版本。
> 随附最小更新包：`pmplatform-update-V4.5.3.zip`（不含 `data/`、`input/`，不动服务器现有数据与账号）。

---

## 0. 影响面总览（先看这张表）

| 项 | 结论 |
|---|---|
| 需要点「更新数据」吗 | **不需要**。七个版本**没有一个**改动数据管线，`analysis_data.json` / `yitian_data.json` 口径零变化 |
| 后端要覆盖吗 | **要**。V4.5.2 改了 `auth.py` / `server.py`（权限模型），其余六版纯前端 |
| 会改写服务器上的数据文件吗 | **会且仅有一处** —— 首次启动时自动迁移 `data/accounts.json`（详见 §1.3），**迁移前会自动备份** |
| 新增 `data/*.json` 文件吗 | 没有 |
| 页面权限（pageKey）有增减吗 | **没有**，仍是 30 个；`allowedPages` / `pageScopes` 存储格式不变 |
| 使用者会察觉的变化 | 三处，见 §1。**其中侧栏结构变化最大，不提前告知会被误判为"功能丢失"** |

## 1. 使用者会立刻察觉的三处变化

### 1.1 侧栏重排 + 分析页收进页内 tab（V4.4.7）—— 请务必转达使用者

侧栏由**按功能类型**改为**按业务对象**分组，组内顺序恒为「总览 → 明细 → 分析」；10 个低频分析页不再单独占侧栏条目，而是**收进所属页面的顶部 tab 条**。侧栏条目 **31 → 24**。

**「项目分析中心」这个分组已解散**，其下 7 个页面各归其业务对象。使用者若按旧习惯找不到入口，多半是它变成了某个页面顶部的 tab，**不是功能被删了**。

**两条访问路径变了**（旧链接会自动跳转，收藏夹不用改，但请知悉）：

| 旧路径 | 新路径 |
|---|---|
| `/insight/board`（回款多维分析） | `/payment/board` |
| `/insight/calendar`（回款日历） | `/payment/calendar` |

### 1.2 页面顶部区统一 + 视觉整理（V4.4.8 / V4.4.9 / V4.5.0 / V4.5.1）

30 个页面的标题与操作按钮位置统一（标题在左、整页级操作在右）；空态、分页、按钮、卡片、小节标题五类元件收敛为共用组件。**功能零变化，只是外观一致了。** 另有 8 个分析页现在会记住你上次选的视图/维度（切走再回来不丢）。

> **顺带提醒一个一直存在、但没人知道的能力**：侧栏底部「显示设置」里可以切换**字号三档（小/中/大）**。
> 觉得当前信息密度偏低（一屏显示的行数少）的使用者，切到「小」档一屏约多 12% 的行。
> 这不是本次新增的功能，是一直都有、只是入口不显眼。

### 1.3 权限配置界面重做（V4.5.2）—— 超管请重点看

**背景**：此前「可访问页面」只能按 6 个业务分组整组勾选，物理上配不出「只能看某一个页面」的账号，而后端一直是逐页精确匹配——**是配置界面的能力落后于后端**。

**本次改动**：
- 页面选择区**补回单页勾选**：分组复选框改三态（全选 / 半选横线 / 不选），组内每一页可单独勾
- 「个别页面单设范围」降级为默认折叠的高级区（此前是平铺的覆盖列表，点击繁琐）
- 新增**「从现有账号复制权限」**（复制源下拉排除超管，不复制密码）
- 权限模型由三层收敛为两层，**删除 `domainScopes` 字段**（生产 20 个普通管理员实测该字段 **0 个账号使用**）

**⚠ 首次启动会自动迁移 `data/accounts.json`**：
- 把旧的 `domainScopes` 物化进 `pageScopes` 后删除该字段，**幂等**（重复启动不会重复改）
- **迁移前自动备份**到 `data/accounts.json.bak-YYYYMMDD`
- 生产环境 20 个账号 `domainScopes` 均为空，**这次迁移实际是空操作**；备份仍会生成
- 若某账号在某个业务域下**一页都无权访问**，该域的范围无处物化，启动日志会打一条 warning（不含账号名）。生产环境不会触发

## 2. 升级步骤（Ubuntu，约 4 分钟）

```bash
# 0) 上传并解压
cd /tmp && unzip -o pmplatform-update-V4.5.3.zip

# 1) 备份 dist、后端、以及账号文件（本次会自动迁移 accounts.json，务必先备份）
TS=$(date +%Y%m%d-%H%M)
sudo cp -r /opt/pmplatform/frontend/dist /opt/pmplatform/frontend/dist.bak-$TS
sudo mkdir -p /opt/pmplatform/backup-$TS
sudo cp /opt/pmplatform/*.py /opt/pmplatform/backup-$TS/
sudo cp /opt/pmplatform/data/accounts.json /opt/pmplatform/backup-$TS/accounts.json

# 2) 覆盖后端（本次后端有改动，必须覆盖）
cd /tmp/pmplatform-update-V4.5.3
sudo cp -f *.py /opt/pmplatform/

# 3) 覆盖前端 dist
sudo rm -rf /opt/pmplatform/frontend/dist
sudo cp -r frontend/dist /opt/pmplatform/frontend/dist

# 4) 重启后端
sudo systemctl restart pmplatform
sudo systemctl status pmplatform --no-pager | head -5

# 5) 确认账号迁移已执行（应能看到自动生成的备份文件）
ls -l /opt/pmplatform/data/accounts.json.bak-*

# 6) 浏览器 Ctrl+F5 硬刷 /pm，左上角版本号应为 V4.5.3
```

## 4. 回滚

```bash
TS=<你升级时用的时间戳>
# 前端
sudo rm -rf /opt/pmplatform/frontend/dist
sudo mv /opt/pmplatform/frontend/dist.bak-$TS /opt/pmplatform/frontend/dist
# 后端
sudo cp -f /opt/pmplatform/backup-$TS/*.py /opt/pmplatform/
# 账号文件（如需，见下方说明）
sudo cp -f /opt/pmplatform/backup-$TS/accounts.json /opt/pmplatform/data/accounts.json
sudo systemctl restart pmplatform
```

**关于 `accounts.json` 要不要一起回滚**：

- 迁移只做了「删掉 `domainScopes` 字段」这一件事。生产 20 个账号该字段本就为空，**删掉与不删对旧版行为完全等价**，因此**通常不需要回滚账号文件**。
- 若回滚后发现某账号可见范围异常，再用上面那行恢复 `accounts.json`。
- 若升级后**已经用新界面改过账号权限**，回滚账号文件会丢失这些改动——请先确认。

`data/` 与 `input/` 的其余内容不受本次升级影响。
