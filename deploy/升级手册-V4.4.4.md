# 升级手册 —— V4.4.4（项目域字段扩散：关闭时间列 + 四页选列/三页范围设置补齐；**纯前端**）

> 适用：已用 /pm 部署在 Ubuntu 服务器（nginx:80 → app 127.0.0.1:8080，systemd，`/opt/pmplatform`，venv `/opt/pmplatform/.venv`）。
> 本包仍是**全量后端快照**（glob 打包全部根 `*.py`），但**后端逻辑较 V4.4.3 无任何改动**——本次改动只在前端 `dist`。
> 随附最小更新包：`pmplatform-update-V4.4.4.zip`。

---

## 0. 本次做了什么

**三件事，都是「让本来就有的数据能被看见、能被筛」，不改任何计算口径。**

1. **`/projects` 新增两列**：「计划关闭时间」「实际关闭时间」，取自 PMIS 里程碑中「项目关闭」节点的计划日/实际日。
2. **「重点跟进」四页选列补齐项目域全量字段**（重点项目进展 / 临时重点跟进 / 风险跟进 / 回款重点跟进）——标签、签约单位、原项目立项日期、计划终验、实际终验、计划关闭、实际关闭等，都可在「选列」里勾出来。
3. **三页「范围设置」补齐取值**（临时重点跟进 / 风险跟进 / 回款重点跟进）：新增可用「计划关闭时间」「实际关闭时间」「原项目立项日期」作筛选条件。

> ### 头号注意
>
> **① 所有新列默认都不显示。** 这是设计如此——四页本就列多，新列一律默认隐藏，需要谁自己在「选列」里勾。勾选状态按登录账号记住。
>
> **② 本次无需点「更新数据」。** 关闭时间来自现有里程碑数据，前端直接派生，不经数据管线。只换 `dist`、重启、硬刷即可。
>
> **③ 已配好的「范围设置」条件零影响。** 本次只**新增**字段，没有改动任何现有字段的内部标识；老条件原样有效、匹配结果不变。
>
> **④ 换 dist 后务必硬刷。** `Ctrl+F5` 清缓存才看得到 V4.4.4。

| 内容 | 需更新数据? |
|---|---|
| `/projects` 两个关闭时间列 | **否**（纯前端派生） |
| 四页选列补齐 / 三页范围设置补齐 | **否** |

## 1. 升级步骤（Ubuntu，约 3 分钟）

```bash
# 0) 上传并解压
cd /tmp && unzip -o pmplatform-update-V4.4.4.zip

# 1) 备份 dist
TS=$(date +%Y%m%d-%H%M)
sudo cp -r /opt/pmplatform/frontend/dist /opt/pmplatform/frontend/dist.bak-$TS

# 2) 覆盖前端 dist（本次核心）
cd /tmp/pmplatform-update-V4.4.4
sudo rm -rf /opt/pmplatform/frontend/dist
sudo cp -r frontend/dist /opt/pmplatform/frontend/dist

# 3) （可选）全量覆盖后端 .py —— 逻辑与 V4.4.3 一致,覆盖只为保持文件同版
sudo cp -f *.py /opt/pmplatform/

# 4) 重启后端
sudo systemctl restart pmplatform
sudo systemctl status pmplatform --no-pager | head -5

# 5) 浏览器 Ctrl+F5 硬刷 /pm,左上角版本号应为 V4.4.4
```

## 2. 升级后验证清单

- [ ] 左上角版本号 **V4.4.4**
- [ ] `/projects` → 「选列」里能看到「计划关闭时间」「实际关闭时间」，**默认未勾选**
- [ ] 勾出这两列后，随便挑 3 个项目，与 `/project/:id` 里「进度里程碑」中「项目关闭」那一行的计划/实际时间**逐个对得上**
- [ ] 四页（重点项目进展 / 临时重点跟进 / 风险跟进 / 回款重点跟进）→ 「选列」里出现项目域字段（标签、签约单位、关闭时间等），**默认都未勾选**
- [ ] 勾出若干新列后：点列头**能排序**、列头**筛选能列出值**、**导出的 xlsx 里该列有值**（三处都要有值）
- [ ] 风险跟进页 → 选列里**不应**出现 `setupDate`、`orgL4` 这类英文列名；「项目金额」仍是**万**、数值与升级前一致
- [ ] 三页「范围设置」→ 打开后原有条件**仍在**、匹配数量与升级前一致；新增「计划关闭时间」条件能正常筛出结果
- [ ] 不同账号登录，各页数据范围与升级前一致（新列同样受数据范围约束）

> 若某项目的两个关闭时间列显示 `-`：说明该项目在 PMIS 里没排「项目关闭」里程碑节点，属源数据缺失，不是升级问题。

## 3. 回滚

```bash
TS=<你升级时用的时间戳>
sudo rm -rf /opt/pmplatform/frontend/dist
sudo mv /opt/pmplatform/frontend/dist.bak-$TS /opt/pmplatform/frontend/dist
sudo systemctl restart pmplatform
```

> 回滚只换回 dist（若第 3 步覆盖了 .py，另从 `bak-$TS` 还原）；`data/`/`input/` 不受影响。
> 各账号的选列勾选状态存在浏览器本地，回滚后新列消失、其余列勾选不受影响。
