# 升级手册 —— V4.4.5（倚天工时**饱和度口径变更**；**纯前端**）

> 适用：已用 /pm 部署在 Ubuntu 服务器（nginx:80 → app 127.0.0.1:8080，systemd，`/opt/pmplatform`，venv `/opt/pmplatform/.venv`）。
> 本包仍是**全量后端快照**（glob 打包全部根 `*.py`），但**后端逻辑较 V4.4.4 无任何改动**——本次改动只在前端 `dist`。
> 随附最小更新包：`pmplatform-update-V4.4.5.zip`。

---

## 0. 本次改了什么

**倚天工时「饱和度」换了分母。这是口径变更，升级后页面上的饱和度数字会变——属预期，不是故障。**

```
旧：饱和度 = 个人总工时 ÷ (区间工作日数 × 8)     ← 全员同一个分母
新：饱和度 = 个人总工时 ÷ (该员工填写天数 × 8)   ← 每人分母不同
```

- **填写天数** = 该员工在区间内**有工时记录的不同日期数**，且**排除 `holidays.csv` 标记的非工作日**。
- **分子不变**：仍是全量工时（含管理类、假期类）。

> ### 头号注意
>
> **① 数字会变，这是本次升级的目的。** 新口径衡量的是「填报的那些日子填得实不实」，不再是「该填的都填了没」。
>
> **② 「欠填 / 达标 / 未按时填写 / 加班」四项口径完全没变。** 它们相对**应填基准**（区间工作日 × 8）计算，与饱和度解耦。升级后这几处的人员名单应与升级前**逐人一致**——这是本次最重要的验收点。
>
> **③ 三处列名/图例改了。** 「基础工时」→「**填报基准**」（概览页组织汇总表与柱图、统计分析页员工明细表），因其数值含义已变。统计分析页饱和度 TOP10 图的参考线**仍叫「基础工时」**，那里确实还是应填基准。
>
> **④ 本次无需点「更新数据」。** 只换 `dist`、重启、`Ctrl+F5` 硬刷。

### 升级后会看到的三个变化（都属预期）

| 现象 | 原因 |
|---|---|
| 只填了少数几天但填满的人，饱和度**明显上升** | 例：应填 2 天、只填 1 天且填满 8h → 旧 50%、新 **100%** |
| 完全没填的人饱和度显示 `-`（原为 0%） | 填写天数 0 → 分母 0 → 无意义，显示 `-`；此人仍在「完全未填」名单与欠填统计中 |
| 节假日加班会**拉高**饱和度 | 那天的工时进分子，但那天不算工作日、不进分母 |

| 内容 | 需更新数据? |
|---|---|
| 饱和度口径变更 + 三处列名 | **否**（纯前端，不碰数据管线） |

## 1. 升级步骤（Ubuntu，约 3 分钟）

```bash
# 0) 上传并解压
cd /tmp && unzip -o pmplatform-update-V4.4.5.zip

# 1) 备份 dist
TS=$(date +%Y%m%d-%H%M)
sudo cp -r /opt/pmplatform/frontend/dist /opt/pmplatform/frontend/dist.bak-$TS

# 2) 覆盖前端 dist（本次核心）
cd /tmp/pmplatform-update-V4.4.5
sudo rm -rf /opt/pmplatform/frontend/dist
sudo cp -r frontend/dist /opt/pmplatform/frontend/dist

# 3) （可选）全量覆盖后端 .py —— 逻辑与 V4.4.4 一致,覆盖只为保持文件同版
sudo cp -f *.py /opt/pmplatform/

# 4) 重启后端
sudo systemctl restart pmplatform
sudo systemctl status pmplatform --no-pager | head -5

# 5) 浏览器 Ctrl+F5 硬刷 /pm,左上角版本号应为 V4.4.5
```

## 2. 升级后验证清单

- [ ] 左上角版本号 **V4.4.5**
- [ ] `/yitian` 概览 → 「平均饱和度」有值；组织汇总表列名为**「填报基准」**，其**合计 = 各行之和**（不再是「某个数 × 人数」）
- [ ] `/yitian/analytics` → 员工明细表**「填报基准」**列**各人数值不同**（升级前全员相同，这是最直观的差异）
- [ ] 同页饱和度 TOP10 图的参考线仍标**「基础工时」**且为一个固定值，与各人「填报基准」不同——两者本就是两个数
- [ ] **【最重要】**「未按时填写」清单、「达标 / 欠填」分类、加班人数与工时 → 与升级前**逐人完全一致**
- [ ] 找一个只填了少数几天的员工：饱和度明显高于升级前，但**仍在**「未按时填写」清单里
- [ ] 找一个零记录员工：饱和度显示 `-`，且仍在「完全未填」名单与欠填统计中
- [ ] `/yitian/trend` → 饱和度趋势曲线有值；含假期的整周不画成 0%

> 若第 5 项（欠填/加班名单）与升级前**不一致**，请立即回滚并反馈——那说明欠填判断被误接到了新分母上。

---

## 3. 回滚

```bash
TS=<你升级时用的时间戳>
sudo rm -rf /opt/pmplatform/frontend/dist
sudo mv /opt/pmplatform/frontend/dist.bak-$TS /opt/pmplatform/frontend/dist
sudo systemctl restart pmplatform
```

> 回滚只换回 dist（若第 3 步覆盖了 .py，另从 `bak-$TS` 还原）；`data/`/`input/` 不受影响。
> 口径随前端代码走，回滚后饱和度即恢复旧口径。
