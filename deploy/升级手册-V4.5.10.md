## 1. 本次修了什么

对应你上线 V4.5.9 后反馈的四条。

### 1.1 收件箱看不出一条回复是哪个项目 → 新增「涉及项目」列

蓝信回复表格此前**一列项目信息都没有**，要判断一条回复说的是哪个项目，只能点开「归入」抽屉看它预填了什么。

现在新增一列：

- **H5 反馈**的条目直接显示 `项目编号 + 项目名称`（这是员工点开哪张卡片时就确定的事实）。
- **文本回复**没有项目信息，显示的是按发送台账推测出来的候选项目，并**明确标注「推测」**——猜的和确定的不混为一谈。
- 两者都没有的显示 `-`。

### 1.2 ⚠ 归入之后在对应位置找不到内容（这条是重点，请读完）

**这是一条从 V4.0.5 就埋着的缺陷，不是 V4.5.9 引入的**，只是此前入站通道一直不通、没人真正用过「归入」，所以从未暴露。

**成因**：归入是按项目编号直接把内容写进目标跟进库的，**写入永远成功**；但四个可归入的目标域里，有**三个只显示项目全集的一个子集**：

| 目标域 | 页面上哪些项目才有行 | 风险 |
|---|---|---|
| 回款重点跟进 | 该页「范围设置」命中的项目 | **范围没配时，整页一行都不显示** |
| 临时重点跟进 | 每个实例各自的「范围设置」命中的项目 | 同上，且每个实例各管各的 |
| 重点项目进展 | 只有重点项目（级别 P1，或 TOP1000 客户且合同 > 100 万元） | 普通项目**永远**不会有行 |
| 风险跟进 | 未设范围时显示全部 | 无此风险 |

于是：**项目不在那一页的行集里 → 内容确实写进去了，但那一页永远渲染不出来**，而收件箱里那条已经被标成「已归入」、按钮转灰、全程没有任何报错。你去对应位置找不到内容，就是这个原因。

> 如果你说的「归档」指的是跟进页那个归档按钮，**症状同源**：归档保存的是页面上当前可见的那些行，看不见的自然也不会被归档带走。

**本次修法**：

- 归入抽屉里现在**常驻显示**「将追加到『本周工作进展』列」这类提示——归入完直接知道去哪一列看。
- 目标页渲染不出这一行时，抽屉里**常驻一条橙色告警**，并且点「确认归入」时**再弹一次二次确认**。告警分两种措辞，因为对你要做的事完全不同：
  - 「**该页尚未设置范围，当前一行都不显示**」→ 你要先去那一页把范围建起来；
  - 「**项目 X 不在该页的范围设置内**」→ 你要么调范围，要么换个目标域。
- **故意没有做成硬拦截**：范围设置和重点项目判定都是会变的，你完全可能打算先归入、之后再把范围调过来。硬拦会把这条路堵死。所以是「说清楚后果 + 要你确认」，确认了照样写。

### 1.3 归入之后无法调整 → 新增「撤销归入」

归入此前是**一次性且不可逆**的：写完就转灰，选错域 / 选错项目 / 选错临时跟进实例都没法重来，唯一的出路是把整条回复删掉——连员工的原话一起丢。

现在已归入的条目多一个「**撤销归入**」按钮（超管专属，有审计记录）。撤销之后该条恢复成「未归入」，可以重新归入，也可以换一个域。

> **⚠ 撤销只解除收件箱这一侧的标记，不会删掉已经写进跟进页的那段正文。**
> 原因：那段正文是**追加**进富文本字段的，你很可能已经在上面接着编辑过；按内容去反向摘除不可靠，失手就是删掉别人手写的跟进——比留一段冗余文本严重得多。
> 所以撤销后，列表上会**持续显示**「曾归入 XX · 项目 YY（已撤销，该处内容未自动删除）」，你自己决定要不要去那一页清掉。

### 1.4 想验真实数据只能在生产上全员真发 → 推送可勾选收件人

「预览并推送」抽屉里，每位收件人前面现在有一个勾选框，顶部有「全选」。

- **默认全选**，什么都不改的话行为和以前一模一样。
- 取消勾选后，**只会推送给还打着勾的那些人**，其余人收不到任何消息。
- 部分推送时二次确认框会明确写「只向勾选的 N 人推送（本次计划共 M 人，其余不会收到）」。
- 全部取消勾选时推送按钮**禁用**——不会退化成「一个都没勾就发给所有人」。
- 审计记录里会标注「指定收件人 N/M 人」，事后能查出来这次是选发还是发失败了。

> 这样就可以只勾自己一个人，做一次带真实数据的端到端验证，而不打扰任何其他人。

## 2. 升级步骤

以下命令假设应用装在 `/opt/pmplatform`、服务名 `pmplatform`，请按实际情况替换。

### 2.1 备份（务必先做）

```bash
cd /opt
sudo tar czf pmplatform-backup-$(date +%Y%m%d-%H%M).tar.gz pmplatform
ls -lh pmplatform-backup-*.tar.gz
```

### 2.2 上传并解压更新包

```bash
cd /tmp
# 把 pmplatform-update-V4.5.10.zip 传到 /tmp
unzip -o pmplatform-update-V4.5.10.zip
ls pmplatform-update-V4.5.10/
```

### 2.3 覆盖后端代码与前端产物

```bash
sudo systemctl stop pmplatform

# 后端 .py（更新包里是全部根级 .py，直接整体覆盖）
sudo cp /tmp/pmplatform-update-V4.5.10/*.py /opt/pmplatform/

# 前端 dist：先删旧的再拷新的，避免残留旧 hash 文件
sudo rm -rf /opt/pmplatform/frontend/dist
sudo cp -r /tmp/pmplatform-update-V4.5.10/frontend/dist /opt/pmplatform/frontend/

# pmisdata 脚本（如果这台机器在用「下载数据」功能）
sudo cp /tmp/pmplatform-update-V4.5.10/pmisdata/* /opt/pmplatform/pmisdata/ 2>/dev/null || true

sudo chown -R pmplatform:pmplatform /opt/pmplatform   # 按实际运行用户替换
```

> **⚠ 不要覆盖服务器上的 `data/`、`input/`、`pmisdata/config.json`。**
> 更新包里**本来就不含**这三样：`data/` 是你的业务数据与账号，`input/` 是数据源，
> `pmisdata/config.json` 存的是超管在页面里贴的 PMIS 会话 cookie——用开发机那份覆盖过去，
> 「下载数据」会立刻失效，而报错长得像「PMIS 登录过期」，很难想到是升级覆盖导致的。

### 2.4 重启并确认

```bash
sudo systemctl start pmplatform
sudo systemctl status pmplatform --no-pager
```

浏览器**强制刷新**（Ctrl+F5 / Cmd+Shift+R），确认左上角版本号变成 **V4.5.10**。

> 版本号没变 = `dist` 没换成功，或浏览器还在用缓存。先强刷，再检查 `dist` 目录时间戳。

## 4. 本次仍未验证的部分（如实说明）

- **第 10 条（真实推送给指定的人）在开发机上无法验证**——需要真实的蓝信网关凭证。代码侧已用端到端测试证明「后端真正拿去发送的收件人名单只剩勾选的那些人」，且「全部落空时一次都不调用发送接口」，但**从未对着真实蓝信网关跑过**。
- **归入可见性告警的实际观感**未在浏览器里目验过（开发机无浏览器）；逻辑判定复用的是那几个跟进页**自己在用的同一个函数**，行为一致性有测试保证，但文案排版没有人眼看过。
- **`review.html`（H5 填报页）本次未改动**，V4.5.9 遗留的「从未在真机浏览器打开过」这条仍然成立。
- 若你上次的测试里，收件箱出现过标「**蓝信回复**」（而非「H5 反馈」）的条目，说明**文本回复通道也已经通了**——那是解密与解析两道闸门有史以来第一次真正执行成功。若出现的是标「未解析」的条目，则是卡在这两关之一，`unparsedReason` 会写明是哪一道，报文原文在 `data/lanxin_callback_raw.jsonl` 里可查（这是设计好的降级，不是新故障）。

## 5. 回滚

本次**不改写任何配置文件、不动数据格式**，回滚是干净的：

```bash
sudo systemctl stop pmplatform
cd /opt
sudo rm -rf pmplatform
sudo tar xzf pmplatform-backup-<你的时间戳>.tar.gz
sudo systemctl start pmplatform
```

> 唯一的新增数据痕迹是「撤销归入」会给收件箱条目加一个 `unhandledFrom` 字段。
> 回退到 V4.5.9 后，旧代码**读不到也不会读**这个字段，不会报错，只是界面上不再显示那条撤销提示。

## 6. 已知问题（本次未修，供知悉）

**跟进页「归档」会永久销毁范围外的跟进内容。**
归档保存的快照是**页面上当前可见的那些行**，而「临时重点跟进」的归档配置是「归档即清空」——两者合起来：任何**不在范围设置命中集里**的记录（页面上看不见 → 不进快照），会在一次归档中被清空且未被留存，**内容彻底消失、没有提示**。

正常手工填写不会产生范围外的记录（得先看得见才填得了），但**归入可以**（本次已加二次确认，但仍允许写入），范围设置被改小、或数据更新后项目掉出范围也可以。「回款重点跟进」与「风险跟进」配的是「留存不清空」，不受影响。

未在本次修复，是因为它要改的是四张跟进表**共用**的归档语义，影响面远超这次报障的范围。已记入 backlog（L-63），要不要动请你定。
