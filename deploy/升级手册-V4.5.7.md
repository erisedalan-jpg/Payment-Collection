## 1. 本次修的两个问题（现网 V4.5.6 上报的）

两条都是「列在、能选、能排序、能导出，就是没值，且不报任何错」。

### 1.1 「重点跟进」四页的**标签列**取不到值，整列空白

影响 **重点项目进展 / 临时重点跟进 / 回款重点跟进 / 风险跟进** 四页。修复后标签口径与 `/projects`、`/project/:id` 完全一致（手动标签 ∪ 规则派生标签）。

**同一个原因还连带修好一处**：超管「范围设置」里按**标签**加筛选条件，此前恒不匹配任何项目、且没有任何提示。现在可用。

### 1.2 **时间差列**配好计算方式后不计算，恒显 "-"

当时间差列的「指定列」或「被减列」选的是**自定义日期列**时，一律算不出来。而「列设置」的候选下拉本来就把自定义日期列列在里面，是主要用法。修复后正常出数。

> **注意（不是故障）**：**被引用的那个日期列本身没填值的行，仍然显示 "-"**，这是正确行为。只有填了日期的行才有天数。

## 2. 升级步骤（Ubuntu，约 1 分钟，无需停机）

```bash
# 0) 上传并解压
cd /opt   # 按实际部署路径调整
unzip -o pmplatform-update-V4.5.7.zip
cd pmplatform-update-V4.5.7

APP=/opt/pmplatform          # 按实际路径调整

# 1) 备份现有 dist
cp -r $APP/frontend/dist $APP/frontend/dist.bak-$(date +%Y%m%d)

# 2) 原子替换 dist（先落到同一文件系统的临时目录，再一次性 mv，避免半份状态）
rm -rf $APP/frontend/dist.new
cp -r frontend/dist $APP/frontend/dist.new
rm -rf $APP/frontend/dist.old
mv $APP/frontend/dist $APP/frontend/dist.old && mv $APP/frontend/dist.new $APP/frontend/dist
rm -rf $APP/frontend/dist.old

# 3) 不需要重启后端、不需要点「更新数据」

# 4) 浏览器 Ctrl+F5 硬刷 /pm，左上角版本号应为 V4.5.7
```

> **包里的 `.py` 和 `pmisdata/` 可以忽略**：打包脚本固定带上全部后端代码，但本次它们与现网**逐字相同**。覆盖不会出错，只是没有必要。
>
> **为什么要 Ctrl+F5**：JS/CSS 文件名带内容哈希、会自动换新，但 `index.html` 可能被浏览器或前置 nginx 缓存住，硬刷可确保拿到新的入口文件。

## 5. 附：这两个问题为什么在 V4.5.6 没被发现

写在这里备查，不影响部署。

- **标签列**：既有契约测试断言的是「借入列的值不是 `undefined`」，而空数组 `[]` 满足这个条件——**结构在、语义死**，测试全绿。本次已把该断言改成按内容校验。
- **时间差列**：V4.4.6 引入该功能时的四条测试，「指定列」全部选的是**内置日期列**（那类值本来就在行对象上），**从未覆盖「指向自定义日期列」这条主用法**。本次已补齐，并对四个页面各补了一条「视图确实把数据传下去了」的回归测试——因为原来的测试只能证明底层函数会用这个数据，证明不了页面真的传了它。
