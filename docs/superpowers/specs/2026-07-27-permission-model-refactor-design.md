# 权限模型与配置界面重构（V4.5.2）设计

> 状态：待实施　｜　版本：V4.5.2（Z 级，用户钦定）　｜　日期：2026-07-27
> 前置：本设计由 `/grill-me` 会话产出，Fable 5 出方案、Opus 5 审查并核实事实。
> 归属：第四期「权限配置统一重构」，整体前端优化的收官期。

## 1. 要解决什么

超管的原话：

> 「目前无法完成该配置，建议后续做统一的权限设置重构」
> 「相关权限配置目前过于复杂，希望做统一重构」
> 「目前权限设计过于冗杂，配置不够灵活、简便」

触发场景：想建一个只能看「成本分析」一个页面的账号，配不出来。

两个诉求方向相反 —— **更灵活**要更细粒度，**更简便**要更少层级。本设计的前提是：它们不矛盾，因为病灶不同。

## 2. 事实基础（已核实，勿凭记忆重推）

### 2.1 配不出来是纯界面缺陷

`AdminView.vue:263-270` 的「可访问页面」只渲染 7 个业务分组复选框，**没有任何单页复选框**。`toggleGroup` 整组增删、`groupChecked` 要求整组全中。而后端 `_can_page` 一直是逐页精确匹配（`'*' in pages or page_key in pages`）。

**模型有 30 页粒度，界面只暴露 7 组粒度。** 这是历史上一次「减少点击次数」改版（逐页勾选 → 组级勾选，点击 15+ → 4~5）留下的能力退化。

链路其余各环**均已支持单页粒度，无需改动**：

| 环节 | 位置 | 状态 |
|---|---|---|
| 后端页面门禁 | `server.py:_can_page` | 逐页精确匹配 |
| 前端路由守卫 | `router/index.ts:140` | 按 `meta.pageKey` 逐页判 |
| 侧栏 tab 容器显隐 | `AppSidebar.vue:14-18` `resolveItem` | 容器 `to` 按权限动态求值，指向组内首个有权 tab |
| 登录落地页 | `stores/auth.ts:75` `firstAllowedPath` | 遍历 `ALL_PAGE_LINKS`，含 tab 页（`auth.test.ts:120` 有回归） |

只勾 `insight-costdetail` 的账号，侧栏会显示「项目 → 项目分析」直达 `/insight/costdetail`。**唯一堵死的就是配置界面。**

### 2.2 生产环境实测（2026-07-27，20 个普通管理员）

| 维度 | 使用情况 |
|---|---|
| `allowedPages` | 全部在用 |
| `allowedL4` | 全部在用 |
| `pageScopes` | **1 个账号，1 条** |
| `domainScopes` | **0 个账号** |
| `allowedStaff` | **0 个账号** |

**20 个账号里 19 个只用两个维度。** 为 5% 的用例付出的代价，是 100% 的账号都要面对 17 个控件和一个动态覆盖列表；效率损失乘以 20。

注：开发机 `data/accounts.json` 只有 2 个普通管理员，统计不可代表生产。**今后凡涉及"谁在用什么"的判断，一律以生产实测为准。**

### 2.3 冗杂的根源是三期只叠不收

V4.2.0 加员工轴 → V4.3.0 加域层（当时逐页成本高，域是折中）→ V4.3.1 加页层。**页层落地那一刻域层就成了冗余中间层** ——「默认 + 页级例外」能表达域层的一切配置 —— 但 V4.3.1 没有回收它。

超管配一个账号要理解 8 个概念：页面集合、默认 L4、默认员工、域覆盖、页覆盖、三层优先级、显式空 vs 缺省回退、L4 与员工的并集语义。

## 3. 模型改动

### 3.1 收敛为两层

```
旧：pageScopes[页] ?? domainScopes[域] ?? {allowedL4, allowedStaff}
新：pageScopes[页] ??                      {allowedL4, allowedStaff}
```

| 字段 | 处置 |
|---|---|
| `allowedPages` | 保留，语义不变（逐页 + `'*'` 通配） |
| `allowedL4` | 保留，即「默认范围·组织维」 |
| `allowedStaff` | **保留**（用户钦定；见 §8 风险） |
| `pageScopes` | 保留，唯一覆盖层 |
| `domainScopes` | **删除** |

概念从 8 个降到 5 个（页面集合、默认范围、页级例外、通配、并集）。

### 3.2 承重设计 ① —— 安全边界零触碰

**服务端裁剪、并集下发、前端同构收窄三段结构原样保留。** 改动只发生在 `effective_scope` 删一个 fallback 分支。

以下**一律不动**：`domain_union_scope` 的签名、`server.py` 中它的 6 处调用点、`data_scope.filter_analysis_data`、`data_scope.scope_yitian_data`、`config.PAGE_DOMAINS` 与 `config.DOMAIN_PAGES`、商机域 staff 恒清空的特例。

（`_scope_staff_ids` 的**实现**随字段删除而简化——只遍历 `allowedStaff` + `pageScopes`——但**返回语义不变**。）

任何"简化"都不得变成「前端隐藏、后端全量下发」。

**函数签名的取舍**：删域层后 `effective_scope` 的 `domain` 参数不再参与解析，改为 `effective_scope(rec, page_key=None)`（生产调用点只有 2 个，都在 `domain_union_scope` 内部）。

但 **`domain_union_scope(rec, domain, page_keys)` 的签名保持不变**，即使其 `domain` 参数在两层模型下已不参与计算。理由：那 6 处调用点是服务端数据裁剪链路，本期的核心承诺是不触碰安全边界；为一个参数的整洁去动 6 处裁剪调用点，风险收益比不划算。在 docstring 注明「`domain` 仅为调用点兼容保留，两层模型下不参与解析」即可。若 ruff 报 unused-argument，加 noqa 而非改调用点。

### 3.3 承重设计 ② —— 必须物化迁移，不得静默忽略

域覆盖的典型用途是**收窄**（默认 `['*']`、某域限某 L4）。若代码删了域分支而数据里仍有非空 `domainScopes`，该域会回退到**更宽的默认** —— 服务端将下发越权数据，即**权限放大**。

生产虽全空，但备份回滚、其它部署副本、`lts/` 变体都可能带非空数据进入新代码，这道防线必须存在。

**物化规则**（`auth.migrate_domain_scopes(accounts) -> tuple[dict, int]`，幂等）：

1. 跳过超管（`isSuper` 短路）
2. 账号无 `domainScopes` 或为空 → 仅删除该字段（若存在）
3. 非空 → 对该域下每个**已允许**（`'*' in allowedPages or page in allowedPages`）**且尚无 `pageScopes` 条目**的页面，写入该域的 `{l4, staff}`；然后删除 `domainScopes`
4. **已有 `pageScopes` 条目的页不被覆写** —— 页层优先级本就高于域层，覆写会改变语义

**调用时机**：服务启动、`seed_default_accounts()` 之后。有改动时先备份 `accounts.json → accounts.json.bak-YYYYMMDD`（一次升级只备一次）。

**向后兼容红利**：物化目标是最高优先级层，所以升级后的数据文件拿回旧版程序跑行为也完全一致（旧版读不到 `domainScopes` 走缺省，页层照常命中）。双向兼容。

**生产实际效果**：20 个账号 `domainScopes` 全空 → 纯空操作；那 1 条 `pageScopes` 原样带过；升级前后每页生效范围逐位相同。

### 3.4 后端改动清单

`auth.py`：
- `_make_user` / `create_account` / `update_account` / `add_account` / `edit_account`：删 `domain_scopes` 参数
- `public_user`：删 `domainScopes` 键
- `_validate_domain_scopes`、`_SCOPE_DOMAINS`：删除
- `effective_scope`：删中间层分支（原 242-244 行），签名 `(rec, domain, page_key=None)` → **`(rec, page_key=None)`**
- `domain_union_scope`：**签名不变**，内部两处调用改为新签名；docstring 注明 `domain` 不参与解析
- 新增 `migrate_domain_scopes`

`config.py`：**不动**（`PAGE_DOMAINS` / `DOMAIN_PAGES` 仍被 `domain_union_scope` 调用点、例外下拉过滤、空范围提示消费）。

`server.py`：
- `handle_admin_account_create` / `handle_admin_account_update`：不再传 `domainScopes`；**收到该字段即忽略并记 warning 日志，不返回 400** —— 防旧版前端缓存页面提交后炸掉
- `_scope_staff_ids`：删 `domainScopes` 遍历（仅留 `allowedStaff` + `pageScopes`）
- 审计 detail：删「分域%s」片段

### 3.5 前端改动清单

- `lib/pageScope.ts`：`effectiveScope` 删域分支。**`PAGE_DOMAINS` 保留** —— 例外下拉过滤与空范围提示仍依赖它
- `lib/admin.ts` `AdminAccount`、`lib/auth.ts` `AuthUser`：删 `domainScopes`
- `AdminView.vue`：见 §4

## 4. 界面设计

弹窗宽度 520px → **640px**（容纳 30 个复选框）。

```
┌─ 新建账号 ──────────────────────────────────────┐
│ 从现有账号复制  [ 选择账号（可选）        ▾ ]   │  ← 仅新建时显示
│                                                  │
│ 账号     [________]  密码 [________]             │
│ 显示名   [________]                              │
│                                                  │
│ ── 能看哪些页面 ──                               │
│ [ ] 全部页面（含未来新增）                       │
│  [-] 项目   [ ]项目总览 [ ]在建项目 [ ]已关闭    │
│             [ ]项目动态 [x]多维分析 [x]成本分析  │
│  [ ] 回款   [ ]回款总览 [ ]回款项目 ...          │
│  [ ] 商机   ...      [ ] 倚天工时  ...           │
│  [ ] 重点跟进 ...    [ ] 工具 ...                │
│      ↑ 组复选框三态：点组名一击全组，点单页只动单页 │
│                                                  │
│ ── 能看哪些数据 ──                               │
│ 可见 L4      [ 全部 L4 / 多选部门          ▾ ]   │
│ 额外放行员工 [ 按姓名多选（可空）          ▾ ]   │
│                                                  │
│ ▸ 高级 · 个别页面单设范围                        │  ← 默认折叠
│   [页面 ▾][L4 ▾][员工 ▾] ✕     + 添加例外       │
│                                                  │
│ ⚠ 已勾选的「回款节点」等 2 页生效范围为空，将看不到数据 │
│                              [取消] [创建]       │
└──────────────────────────────────────────────────┘
```

### 4.1 三态组复选框

组复选框用 Element Plus 原生 `indeterminate`。这是「组级快捷」与「单页精度」统一在同一控件的标准解法：整组仍 1 击（不回退 V4.3.1 省点击的成果），单页可达（补上缺失粒度）。

- `groupChecked(g)`：组内全部页面已勾 → true
- `groupIndeterminate(g)`：组内部分已勾（既非空也非全） → true
- 勾中「全部页面」（`'*'`）时，组区域隐藏（沿用现有 `v-if` 行为）

分组来源沿用 `NAV_GROUPS = NAV_SECTIONS.map(s => ({..., links: sectionPageLinks(s)}))` —— `sectionPageLinks` 会把 tab 容器展开成其下 tab 页，10 个分析页因此可勾。

### 4.2 高级区

- 默认折叠（自绘折叠头 + `v-show`，不用 `el-collapse` —— V4.5.0 踩过它自带 `border-top/bottom` 的坑）
- **有存量值时强制展开**：`openEdit` 时若 `pageScopes` 非空 → `advancedOpen = true`。绝不把在用配置藏起来
- 例外行：`[页面下拉][L4 多选][员工多选][删除]`，无 `domain:` / `page:` 前缀（只剩一种目标类型）

### 4.3 例外目标下拉只列可见页

```
候选 = (allowedPages 含 '*' ? 全部页 : 已勾选页) ∩ PAGE_DOMAINS ∩ (≠ governance)
```

给没勾的页配范围本是无意义配置，顺手堵死。配「只看成本分析」的账号，这个下拉只有 1 项。

`governance` 的排除是**沿用既有语义**（它虽在 `PAGE_DOMAINS` 中但历来不进此下拉），本期不改变。

### 4.4 孤儿例外清理

`_validate_page_scopes` 只校验 pageKey 合法，**不校验该页是否在 `allowedPages` 里** —— 取消勾选某页后它的例外会残留。

`buildScopes()` 提交前按 `allowedPages` 过滤，丢弃孤儿条目（`'*'` 时不过滤）。

### 4.5 空范围提示（不硬拦）

计算「已勾选 ∩ 有数据域 ∩ 生效范围为空」的页面，非空则在页脚上方显示黄色提示，**不阻断保存**。

**必须按 `PAGE_DOMAINS` 判定** —— `data` / `budget` / `about` 三个工具页没有数据域，硬拦或误判会拦住只勾工具页的账号，重蹈「配不出来」的覆辙。

### 4.6 从现有账号复制权限

**入口**：新建弹窗顶部一个可搜索下拉（编辑模式不渲染）。不在列表行加按钮 —— 操作列 160px 已有编辑/删除两个 link，且 20 个账号下拉搜索比表格翻找快。

**复制内容**：`allowedPages` / `allowedL4` / `allowedStaff` / `pageScopes` 四件套。

**不复制**：账号名、**密码**、显示名。

**承重设计 ③ —— 复制源下拉排除超管**：超管记录是 `allowedPages: ['*']` + `allowedL4: ['*']`，复制它等于一键造出全权限的准超管。要全权限必须手动勾「全部页面」+「全部 L4」，保持为显式动作。

复制后若 `pageScopes` 或 `allowedStaff` 非空 → 自动展开高级区。选完可继续手工改。

纯前端行为（只填 `form`），**不需要任何后端改动**。

### 4.7 验收基准

| 场景 | 配置动作数 |
|---|---|
| 只看成本分析 | **3**（勾 1 个复选框 + 选 L4 + 创建） |
| 管两个部门全部项目 | **2~3**（勾「全部页面」+ 选 2 个 L4） |
| 照着老王再建一个 | **2**（选复制源 + 填账号密码） |

## 5. 测试策略

### 5.1 迁移等价性（最重要的回归安全网）

构造带非空 `domainScopes` 的 fixture，断言：**对全部账号 × 全部 26 个有域页面，迁移前的三层解析结果 == 迁移后的两层解析结果**。

对拍需要旧实现 —— 在测试文件内联一份 `_legacy_effective_scope`（三层版），不依赖被删除的生产代码。

另需三条：空字段幂等（跑两次结果相同）、非空物化等价、**已有页覆盖不被域物化覆写**。

### 5.2 其余

- `effective_scope` 两层语义：页级命中 / 显式空 / 回退默认
- `create_account` / `update_account` 不再接受 `domain_scopes`；传了也不炸（忽略）
- 三态组复选框：全选 / 半选 / 空三态；点组名与点单页互不干扰
- 例外下拉候选过滤；孤儿清理
- 复制：下拉不含超管、四件套被填充、账号密码显示名不被填充、编辑模式不渲染
- 高级区：存量 `pageScopes` 非空时强制展开

### 5.3 退役 —— 附带一个必须警惕的假绿陷阱

`test_auth_domain_scope.py` **整个文件删除或重写为迁移测试**，跨语言同步测试（`PAGE_DOMAINS` 前后端一致）**保留不动**。

**陷阱**：该文件的断言形如 `auth.effective_scope(rec, "project") == (["D1"], ["E1"])`。签名改为 `(rec, page_key=None)` 后，`"project"` 会被当作 **page_key** 传入 —— 它不是合法 pageKey，`pageScopes` 里查不到，于是回退默认范围，**恰好等于原断言值，测试静默变绿**。

三条断言（`test_auth_domain_scope.py:11-13`）会以这种方式假绿，只有 `:20`（域覆盖生效）会真红。

**因此：该文件必须整体删除或重写，绝不允许「跑一遍看哪条红了就改哪条」。** 靠改断言凑绿会留下三条什么都没验证的测试。

（对照：`test_auth_page_scope.py` 的三参数调用会直接 TypeError，`:16` 的两参数调用会真红 —— 这个文件的失败是诚实的。）

## 6. 不做的事

- **不做「按组批量添加例外」** —— 域层零使用已证明「按域配范围」不是真实需求
- **不做角色/权限模板/继承** —— 20 个账号规模下属过度设计；复制功能已覆盖「照着建一个」的真实诉求
- **不动 `/insight` 回款完成率口径**等既有技术债
- **不改 `governance` 不进覆盖下拉**的既有语义

## 7. 迁移与部署

生产 20 个账号 `domainScopes` 全空 → 迁移是删字段的空操作，**零风险**。那 1 条 `pageScopes` 原样带过。

升级后数据可被旧版程序正确读取（§3.3 双向兼容），回滚安全。

## 8. 风险与技术债

**① 项目经理重名过匹配（既有债，本期不修）**
`allowedStaff` 在项目域是按**项目经理姓名**匹配（`data_scope.allowed_project_ids` 的 `pm in pmset`）。同名不同部门的项目经理会被一起放行。保留 `allowedStaff` 意味着这笔债继续存在。生产当前 0 个账号使用该维度，暂无实际影响；一旦启用需先修此债。

**② 删域层后新增页面的范围归属**
今后新增页面若未单独配例外，一律落到默认 `allowedL4`。旧模型下它会继承域覆盖 —— 但域层零使用，此差异在生产上不产生行为变化。属能力取舍，非缺陷。

**③ `allowedStaff` 生产实测为 0**
用户表述「线上生产已经有使用」与实测（0 个账号）不符，仍按用户决定保留。理由是代价结构：保留成本是一个下拉控件加一份同构逻辑，删除是不可逆的能力放弃。
